# ระบบนิเทศออนไลน์ สถาบันศึกษาปอเนาะ จ.นราธิวาส (2569)

โปรเจกต์พัฒนาแยกจากระบบตาดีกา — มี Apps Script project, ฐานข้อมูล และโฮสต์หน้าเว็บของตัวเอง

## โครงสร้าง

```
├── apps-script/          # โค้ด Google Apps Script (backend API)
│   ├── รหัส.js           # ตัวประมวลผล API (ปอเนาะล้วน ไม่มีโค้ดตาดีกา)
│   └── appsscript.json   # manifest
├── index.html            # หน้าเว็บหลัก (โฮสต์ผ่าน GitHub Pages)
├── .clasp.json           # กำหนด mapping กับ Apps Script project (clasp)
├── deploy.ps1            # สคริปต์ deploy อัตโนมัติ (push → version → redeploy)
└── tests/
    ├── login_flow_test.cjs       # ทดสอบแบบนิเทศ คะแนน รายงาน และตำแหน่งแถวแบบออฟไลน์
    ├── workflow_browser_test.cjs # ทดสอบ flow บนคอมพิวเตอร์/มือถือด้วย API จำลอง
    └── crud_test.ps1             # ใช้ API จริงและแก้ไขชีต ห้ามรันเป็น smoke test ทั่วไป
```

## การ deploy

```powershell
powershell -ExecutionPolicy Bypass -File deploy.ps1
```

- ต้อง `clasp login` บัญชีเจ้าของ project ก่อน
- ใช้ `.clasp.json` (`rootDir=apps-script`) push code ชุดเดียวกับใน repo
- หมายเลข version ใหม่ถูกสร้างและ redeploy ชี้ deployment เดิม (URL คงเดิม)

## ขั้นตอนใช้งาน

เข้าสู่ระบบ → เลือกรูปแบบ → เลือกสถาบัน / ดูประวัติ → กรอกแบบนิเทศ → ตรวจสอบและยืนยัน → บันทึกสำเร็จ / กลับหน้าแรก

- **ทั่วไป:** แบบที่ 8 หน้าเดียว 16 ข้อ รวม 32 คะแนน ตัวเลือก 2 / 1 / 0 / N/A
- **เต็มรูปแบบ:** เลือกเครื่องมือแบบที่ 1–7 ก่อนเลือกสถานที่ บันทึกทีละแบบ หลังสำเร็จทำแบบอื่นที่สถาบันและรอบเดิมได้
- ประวัติเดิมเปิดแก้ไขได้ทุกแบบโดยระบบเลือกรูปแบบให้เอง การลบต้องยืนยันและคงการสำรองข้อมูลเดิมของ backend
- หน้าแบบนิเทศแสดงเฉพาะงานที่กำลังกรอก ข้อมูลสถาบัน/แผนที่เปิดเพิ่มได้ ประวัติและรายงานอยู่ที่หน้าเลือกสถาบัน
- เตือนก่อนออกจากข้อมูลที่ยังไม่บันทึก บันทึกไม่สำเร็จยังคงข้อมูลเดิม และไม่ส่งซ้ำอัตโนมัติ หากเครือข่ายขาดขณะส่งให้ตรวจประวัติก่อนส่งอีกครั้ง
- หลังบันทึกสำเร็จจะไม่กลับไปฟอร์มว่าง การเปิดประวัติไม่สำเร็จไม่เปลี่ยนสถานะการบันทึกสำเร็จ

## ทดสอบโดยไม่กระทบข้อมูลจริง

```powershell
node tests/login_flow_test.cjs
node tests/workflow_browser_test.cjs
```

ชุดทดสอบเบราว์เซอร์ต้องมีแพ็กเกจ `playwright` (ติดตั้งในสภาพแวดล้อมทดสอบหรือกำหนด `NODE_PATH`) และ Microsoft Edge; ตั้ง `PONDOK_BROWSER_CHANNEL=chrome` ได้หากใช้ Chrome แทน ชุดทดสอบดักทุกคำขอ API และใช้ข้อมูลจำลองเท่านั้น อนุญาตให้อ่านเฉพาะ SweetAlert รุ่นที่หน้าเว็บใช้อยู่จาก CDN เพื่อทดสอบหน้าต่างยืนยันจริง ตั้ง `PONDOK_SCREENSHOT_DIR` เป็นโฟลเดอร์ที่มีอยู่แล้วเพื่อเก็บภาพหน้าจอได้

## เครื่องมือเต็มรูปแบบ 7 ฉบับ

1. แบบสำรวจข้อมูลพื้นฐานและความพร้อมในการใช้หลักสูตร (ไม่ให้คะแนน)
2. ประเมินการบริหารและการใช้หลักสูตร (8 องค์ประกอบ, 4/3/2/1/N/A)
3. วิเคราะห์หน่วยและแผนการจัดการเรียนรู้ (เชิงคุณภาพ)
4. สังเกตการจัดการเรียนรู้ในชั้นเรียน (9 ด้าน, 0–3)
5. ติดตามการวัด ประเมินผล และพัฒนาการผู้เรียน (เชิงคุณภาพ)
6. สะท้อนผลและแผนพัฒนาหลังการนิเทศ AAR + Action Plan
7. นิเทศติดตามสำหรับผู้ที่ไม่ใช่ศึกษานิเทศก์ (12 ข้อ, 0/1/2)

รอบการนิเทศ: ครั้งที่ 1 การศึกษาสภาพและกำหนดประเด็นพัฒนา · ครั้งที่ 2 การติดตามและสนับสนุนการพัฒนา · ครั้งที่ 3 การประเมินผลและสรุปพัฒนาการ · อื่นๆ ให้ระบุ
